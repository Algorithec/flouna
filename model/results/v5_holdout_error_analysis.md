# Phase 2 - label-consistency audit

The rulings below are corpus-wide, not just about the 38 misses. Each one
was checked against the production contract in
`server/src/modules/chat/llm/prompt.ts`, the V5 generator in
`gen_data_v5.py`, and the training rows themselves. The sealed holdout is
unchanged.

## D1. Dietary: explicit statement first, then the canonical dish map

Where the labels disagree: V5 mixes generations. The V4 rows were repaired
with `detect_dietary(text, item)`, which searches the dish word for veg/nonveg
markers. The V5 rows use `FOOD_DIETARY`, a dish table. The handcrafted
holdout table uses the table too. The table has `masala dosa` and `plain dosa`
but not `dosa`, so `send dosa ASAP` fell back to `any` while every other
dish-implied holdout case (pancakes, cake, brownie, dahi puri, coffee) expects
its dish value.

Ruling: A = explicit word (veg, non-veg, chicken, meat...) or unambiguous dish
in the canonical map; otherwise any. Add `dosa` (and the rest of the ingredient
list) to the map. **holdout-12 is graded B** under this convention and is
expected to remain a miss. The production prompt says dietary is extracted
"if stated"; we keep the dish map because the recommender filters on it and
because 10k training rows plus five of six sealed implied cases use it. This
divergence is recorded here, not hidden.

## D2. Ride vehicle: explicit word only, otherwise any

`gen_ride` and `gen_combo` sample a vehicle even when the sentence never names
one, so the same surface has cab, auto, bike and any labels. The production
contract asks for a vehicle preference; with no preference the honest value is
`any`.

Ruling: map explicit words (bike/motorbike/scooter; auto/rickshaw/auto
rickshaw; cab/taxi/car) to the enum; otherwise `any`. In the audit: holdout-276,
280, 281 (label any) are A; holdout-273, 274, 279, 282 (label cab/auto) are B.
The V6 rule fixes three of the seven and cannot fix the other four.

## D3. Priority: cues in the user's words, then a single deadline rule

Cue order: rating (best, top-rated, badhiya, manchi) > speed (fast, quick,
asap, jaldi, don't want to wait) > price (cheap, sasta, budget, low cost) >
balanced. Cues are matched case-insensitively, so `SASTA` counts and the label
is still lowercase.

Deadline rule: a delivery deadline or a pickup wait with no explicit priority
word means speed. Among ETA-only training rows this convention is 713 speed vs
205 balanced; it is also what the sealed set expects for 336. It contradicts
the sealed labels of 83 and 106, which share the same surface. That pair is
graded C: the generator used hidden state, so no model can separate them. V6
follows the majority and accepts the two misses.

## D4. Item: dish > meal > taste phrase > dietary word > 'food'

The holdout labels show the intended precedence: `lunch` is the item in
"something low cost for lunch"; `food` is the item in "nonvegetarian options"
and "pure veg options"; `something cheesy` stays whole as a mood item. V5
mixed these up. V6 training will use the precedence above. No schema change.

## D5. Phantom pickups are never taught

Up to 545 V5 training rows carry a pickup that the chosen sentence shell
omitted. Three sealed cases (169, 230, 231) carry the same defect. The contract
says pickup is null unless stated; V5's behaviour was right and the benchmark
scored it wrong.

Ruling: strip every pickup whose name is absent from its sentence when
building V6; require an origin cue (`from X to Y`, `X se Y tak`, `pickup at`,
`pick me up from`, `nundi`) to keep one. The three sealed cases are graded B and
will remain misses. They are not rewritten and not trained against.

## D6. Casing is a training problem, not an output post-process

The enum labels are already canonical lowercase, and the evaluator compares
them case-insensitively. The casing failures are cues the model failed to
recognise (`SASTA`, `SE ... TAK`), not labels that need rewriting. Ruling:
include uppercase and mixed-case rows in training; do not add a runtime
lowercasing layer and do not change the enums.

## D7. Shop categories stay the five existing values

`electronics`, `fashion`, `home`, `appliances`, `any`. V5 invented `furniture`
for an office chair, which the server schema rejects. Ruling: train the
item-to-category map with `home` for furniture, and add a validation rule that
rejects any category outside the enum. No sixth category is introduced.

## D8. Action: present in production, absent from the benchmark

The production prompt and schema define 18 action kinds with 12 required
fields, but the sealed 382 contain zero action cases and V5's corpus has none.
V5's only action measurement is the four-prompt probe in
`results/v5_ollama_action_probe.json`, where it answered all four as discovery
food/shop rows (0/4).

Ruling: V6 trains the contract as written, including hard negatives (information
and discovery requests that mention a cart, order or ride but do not authorise
an action, plus yes/no/cancel). Action accuracy is measured on a separate
sealed action set that is never trained on, because the 382-case holdout cannot
measure it. The production prompt is not changed.

## Consequence for the sealed score

Ten of the 38 misses are not fixable without teaching a label the sentence
does not support: 12 (dietary table gap), 83 and 106 (deadline convention),
169, 230, 231 (phantom pickups), 273, 274, 279, 282 (arbitrary vehicles).
If every other miss is fixed, the sealed ceiling is
**372/382 = 97.38%**. An honest 99%
is therefore not reachable on this benchmark; the honest target for V6 is the
ceiling, and the remaining gap is documented label noise.
